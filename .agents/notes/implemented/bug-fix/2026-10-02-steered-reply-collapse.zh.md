# Agent Note: 在 steering 延续同一后端轮次时保留回复

Status: implemented

[English](2026-10-02-steered-reply-collapse.md) | 中文

## 问题

后端轮次可以在生成答案之后继续消费中途引导（steering）的人工输入。折叠步骤阅读模式只保留每轮的最高步骤，因此把该答案藏进本轮唯一的摘要行，使 steering 之前没有可见回复，并把后续工作的摘要放在 steering 之上。按可见 assistant 行统计模型调用数，还会漏掉只产生工具调用的请求及其 token 和耗时。

## 决策

Chat 在人工 `user` 与 `steering` 行处把每个轮次划分为回复分组，分界取认领该输入的步骤；在其步骤开始前记录的行归属本轮下一个步骤。上下文注入留在所属分组内。每个分组保留其最高的 assistant/工具步骤和最后一个含文本的步骤可见。其余 assistant/工具行与上下文行折叠到位于其首个隐藏行处的摘要之后，该摘要拥有独立的 `turn:startStep` 展开标识。

历史省略在整份日志上保留每条人工 `user/message` 之前的最后一个 assistant 步骤和最后一个含文本步骤，以及每轮的最高步骤和收尾步骤。注入的上下文不保留任何步骤。`session.expandSteps` 仍加载一个后端轮次；加载后只打开读者选中的分组。

已加载步骤的模型调用数、token 与耗时来自每个步骤发布的 assistant 数据，其中包括只调用工具的请求。Host 账目对其覆盖的步骤优先，在展开后保持隐藏，且不会再从已加载事件中重复统计。贡献的指标收到分组标识、已物化的隐藏 node key 和记录的计数；被计数的步骤不一定有可见节点。

本决策替代[原始折叠决策](../architecture/2026-08-14-chat-collapses-settled-steps.zh.md)中按轮次分组及按可见行统计步骤的规则；该文仍保留复用 Chat renderer 槽位、展开状态生命周期与贡献排序的理由。[Digest 分页决策](../architecture/2026-09-01-collapsed-step-digest-paging.zh.md)仍负责有界拉取、基于整份日志的保留规则和账目生命周期。

## 考虑过的替代方案

**每条人工 steering 都结束后端轮次。** Steering 有意延续活跃的驱动运行。为修复呈现而改变持久化生命周期语义，会影响模型调度、goal 和其它所有客户端。

**保留每个含文本的中间步骤。** 这样既保留答案，也保留过程叙述，破坏折叠阅读模式。人工输入无需依赖供应商特定的消息阶段即可划分回复。

**只修复 renderer。** 折叠历史页会在 renderer 收到先前答案之前就将其暂留。保留规则与渲染必须一致。

## 后果

继续工作期间及重新打开历史后，先前回复都保持可读。每个摘要描述一段回复；展开一个分组会拉取整个轮次的事件，而其它分组保持收起。展开状态仍局限于挂载的视图，分页仍限制可用于统计的历史。
