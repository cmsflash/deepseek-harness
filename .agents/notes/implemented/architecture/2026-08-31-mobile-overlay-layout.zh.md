# Agent Note: Web frame 的移动端浮层布局

Status: implemented

[English](2026-08-31-mobile-overlay-layout.md) | 中文

## Problem

Web GUI 在任何宽度下都保持分栏布局。`computeColumns` 只有一个断点 `SIDEBAR_AUTO_COLLAPSE`（1024px），而它仅把侧边栏的宽度偏好替换为 56px 的 `SIDEBAR_COLLAPSED` 控制栏——从不移除任何一栏。在 390px 的手机上，这产出了两个面板：一条读不到任何内容的控制栏，加上 334px 的会话区。展开侧边栏更糟，因为侧边栏从不让步：抽屉占据 280px，只给会话留下 110px，用户真正要看的表面反而成了屏幕上最小的部分。

会话栏的下限进一步放大了问题。`CENTER_MIN` 是 640px，其所有占用方都基于该假设布局，但让步链的第 3 步允许会话栏吸收全部亏空。在手机宽度下，会话区以其设计下限的约一半运行，那些假定横向空间充足的行随之损坏：会话头部把 `flex: 1` 的标题簇与 `flex: none` 的工具簇并置，于是工具簇保住了约 150px 的固有宽度，把 230px 的会话标题挤压到仅剩 41px 的可读空间。

这些都无法从插件触达。`root` 是 `single` slot，single slot 确实支持按 priority 遮蔽，但 `SlotCore.register` 拒绝重复声明其他 entry 已声明的子 slot，且组件只能渲染自身 `children` 表所声明的 slot。遮蔽用的 frame 会是一个无法承载 `sidebar`、`conversation` 或 `details` 的空壳；替代路径是禁用 `ui-layout` 的 bundle 行，并重新实现服务、全部四项声明、store、拖动手柄与主题呈现器。溢出问题同样不可触达——它位于其他包内部带哈希的 CSS Modules 中，而跨包导入符号是被禁止的。

## Decision

`computeColumns` 拥有第二个断点 `MOBILE_MAX`（640px，即 deepsuite SM 档位）。在该宽度及以下，求解器不再产出分栏布局：会话栏占据整个 viewport，详情栏解析为零，侧边栏离开栅格流成为浮层抽屉。`Columns` 携带 `overlay` 判别字段，在该布局下 `Columns.sidebar` 报告的是抽屉宽度而非栏宽度，因此 AppFrame 不需要第二个几何来源。控制栏没有移动端形态——390px 屏幕上常驻 56px 的框架装饰正是最初的问题——所以关闭的移动端侧边栏解析为零。

抽屉的尺寸会为会话留出一条可见条带：低于上限时按 `DRAWER_PEEK`（56px）计算，高于上限时取 `DRAWER_MAX`（320px）。这条带使遮罩成为明确的关闭目标，而不是一层不可见的全屏浮层；它同时是真实指针实际能触达的区域——点在遮罩的几何中心会落到抽屉上。

打开控件由 AppFrame 自身渲染。它更自然的归属是会话头部，但 hero 状态不渲染头部，因而关闭的抽屉会让用户失去返回会话列表的入口。frame 是两种状态下都存在的唯一元素。由于抽屉覆盖会话，从抽屉发起的导航也必须关闭它：`ctx.layout.collapseNarrowSidebar()` 是导航侧的动作，ui-sidebar 与 ui-workspace 在新建或打开会话后调用它。

该动作以浮层布局为条件，而非以 `narrow` 为条件。两个断点相距 384px，在其之间（例如 700px 窗口）侧边栏仍是用户主动打开、位于会话旁边的一栏——在那里关闭它会在每次导航时推翻用户的选择。因此 store 在 `narrow` 之外同时镜像 `overlay`，且 `collapseNarrowSidebar` 仅在侧边栏确实覆盖目标时才生效。复用 `narrow` 看起来是对的，却静默破坏了 700px 下的会话切换——这正是浏览器滚动契约场景所捕获的问题。

跨越断点只改变 frame 的几何。slot 占用方保持树位置与 React 标识，且不重写任何宽度偏好，因此变宽后会恢复此前的分栏布局——与让步链原有的纯粹性一致。

AppFrame 测量的是自身盒子而非窗口，对一个可能小于 viewport 的 frame 而言这是正确的，但也使宽度成为「由该宽度选出的布局」的函数。因此，未能改变被观察元素的尺寸变化会把 frame 停留在上一次测量值上；而现在一次测量决定了栏的数量，这个过期读数就可能把布局锁在断点的错误一侧。一个 `window` resize 监听器与 observer 并行执行同一套 rAF 节流测量，使两条路径始终一致。

头部修复归属 ui-conversation，位于其样式表末尾的单个 `@media (max-width: 640px)` 块中。基础规则设置了简写属性（`flex: 1` 解析出 `0%` 的 basis），覆盖规则必须在同等特异性下取胜，因此由源码顺序决定；置于其前的块会静默失效。在手机上标题行换行，标题簇取满宽 basis 以迫使工具簇独占一行，头部则缩进避开 frame 的浮动打开控件。

Markdown 表格在 ui-primitives 中采用同样的处理。单元格的 `min-width: 100px` 加上 32px 横向内边距，使表格的每列最小宽度达到 132px，因此即便是三列的换行优先表格也需要 396px，在约 334px 的消息栏内被迫横向滚动。两项预算在移动端断点一同收窄（64px 下限、16px 内边距），既让下限仍能容纳一个短词、内边距仍能分隔各列，也让窄表格按设计换行。真正宽的表格仍在自身容器内滚动——这在任何宽度下都是它们的约定。

## Alternatives considered

**用插件替代核心补丁。** 之所以否决是因为不可行，而非不理想——见 Problem。值得记录的原因是：“让 GUI 响应式”看起来正是 slot 系统应当吸收的表现层关切，但事实并非如此：slot *声明* 是独占的，因此任何重新组织既有栏位归属的方案都等同于 fork `ui-layout`。

**把断点放进 AppFrame，不动求解器。** `SIDEBAR_AUTO_COLLAPSE` 正是这样做的，因此有先例。否决原因是：该断点只挑选求解器的输入，而移动端布局改变的是*输出*——栏的数量不同。把它放在组件里会让几何契约横跨两个文件，并使 `Columns` 无法描述实际渲染的结果。

**在手机上降低 `CENTER_MIN`，而不是移除控制栏。** 这能去掉挤压运算，却去不掉被浪费的 56px，并削弱一个会话栏占用方在所有宽度下都依赖的常量。移除控制栏是更小的改动：下限保持原有含义，移动端分支在让步链运行前就已返回。

**在手机上隐藏工具簇。** 比换行更省事，但 “Session log” 及其相邻控件是该会话的操作入口，一个在最小屏幕上删除功能的布局修复只是把一种抱怨换成另一种。

## Testing

`columns.client.spec.ts` 以 375/390/414 这些真实设备宽度覆盖移动端分支：两种抽屉状态下的满宽会话栏、peek/上限尺寸、`MOBILE_MAX` 处的精确切换，以及跨断点的纯粹性。两个既有用例原本在 400px 与 500px 断言旧行为——在新契约下它们属于手机宽度——现改为在 `MOBILE_MAX` 之上断言同样的分栏事实。

`app-frame.client.spec.tsx` 覆盖渲染后的 frame：单一轨道、关闭抽屉的 `inert`／`aria-hidden`、打开控件与遮罩关闭、拖动手柄的缺席，以及恢复为分栏布局。

`apps/web/tests/mobile-viewport.e2e.ts` 是包内规格无法承担的浏览器级守卫——jsdom 不解析布局，只有真实引擎才能回答会话区是否真的铺满 viewport、页面是否横向滚动。它在 390px 与 375px 上断言相对 viewport 的事实，而非绝对像素（后者随安装字体在不同平台上不同）。

三个既有 viewport 扫描不再止步于 600–640px，而是延伸到手机宽度，上述表格缺陷正是由此暴露：`message-feedback-layout`（414/390）、`conversation-column-overflow`（414/390）与 `markdown-wide-table`（390）。反馈扫描的锚定断言需要一条手机分支：`useAnchoredPosition` 会把浮层夹回 viewport 内，且留在屏幕内优先于紧贴触发点，因此手机档位会合理地报告非零的触发点间距，而更宽的档位永远不会产生它。

## Consequences

手机布局现在是单栏且会话区满宽，抽屉可达、可关闭，并在导航时自行关闭。`Columns` 增加了一个字段，因此每个构造点都需声明 `overlay`——这是一次编译期推动，促使调用方明确自己指的是哪种布局。

仍有两处缺口，ui-layout 的 README 均已记录。详情栏没有移动端形态：在 `MOBILE_MAX` 以下它始终关闭，因此工具详情等 `details` 占用方在手机上无法访问，需要各自的表面（覆盖会话的 sheet）才能补齐。抽屉也没有滑动手势；它只能通过打开控件、遮罩与导航开合，因为边缘滑动需要一个 frame 目前不具备的手势归属方。

`ui-layout` 现在为打开控件的标签注入 `locale`，`ui-workspace` 为关闭动作注入 `layout`。两者都是普通的服务依赖，但后者值得记录：workspace 浏览区如今依赖布局服务，纯粹是为了配合一个它从不读取的 viewport。
