# Agent Note: 手机视图栈与平台返回操作

Status: implemented

[English](2026-11-26-phone-view-stack.md) | 中文

## Problem

[移动端浮层布局](2026-08-31-mobile-overlay-layout.zh.md)把会话列表放进覆盖在会话之上的抽屉。抽屉是临时面板：遮罩后面露出一条会话，页面打开时停在当前选中的会话，平台自身的返回操作也不起作用。在手机上，聊天应用把列表当作独立的一屏，并通过 Android 的返回操作或 iOS 从左边缘的滑动离开会话。

## Decision

在不超过 `MOBILE_MAX` 时，框架叠放三个全屏视图：会话列表、会话、全屏右侧面板。列表与会话页（中栏加右栏）共用单一网格轨道，会话页滑入并覆盖列表。现有的 `narrowExpanded` 标志选择列表，因此存储只新增一个直接设置的操作；以手机宽度打开的页面从列表开始。

列表之上的每层视图各占一个浏览器历史记录项，并在 `history.state` 中标记其深度。`phone-history.ts` 只在变化时协调记录项与视图：屏幕深度上升时压入记录项，下降时回退其上方的记录项。popstate 落到屏幕深度以下时请求视图关闭，并在视图跟上之前不动记录项，因为右侧面板晚一次渲染才报告关闭；若比较层级而非变化，就会在那次渲染中把已弹出的记录项重新压回。Android 的返回操作、Safari 的边缘滑动和浏览器的前进操作都走这条路径，因此框架无需为它们检测平台。

iOS 主屏幕应用没有浏览器手势，因此仅当 `navigator.standalone` 为 true 时，框架自行跟踪从左侧 24px 内开始的滑动。顶层视图通过 CSS 自定义属性跟随手指；松手时超过宽度 35% 或快速轻扫，就执行与框架返回控件相同的返回操作。

关闭右侧面板属于 ui-sidebar-right，它拥有面板的展开状态。面板通过 `ctx.layout.registerRightbarDismiss` 注册关闭回调；ui-layout 在从面板返回时调用它，不从该包导入任何内容。

## Alternatives considered

**为每个会话建立 URL 路由。** 路由能让每个会话有可分享的地址，但客户端没有路由器，会话选择也不在 URL 中。`history.state` 中的深度标记无需改变会话的打开方式即可支持返回操作。

**在所有触屏设备上处理边缘滑动。** Safari 标签页和 Android 已把边缘手势转为历史遍历；第二个处理器会把同一返回操作执行两次，或与浏览器自身的动画冲突。

## Testing

`phone-history.client.spec.ts` 用带异步遍历的内存历史驱动：压入与回退、从每一层的平台返回、晚报告关闭的面板、两层跳转、前进、恢复视图的重新加载，以及栏式布局。`app-frame.client.spec.tsx` 覆盖不可交互的视图、返回控件和滑动阈值；`apps/web/tests/mobile-viewport.e2e.ts` 覆盖两个视图的全宽、返回控件，以及从会话和从右侧面板的浏览器返回。

## Consequences

新打开的手机页面从列表开始；若重新加载的历史记录项属于会话，则恢复该会话，右侧面板也会自行恢复，因此首次读取只压入记录项，从不回退。若在较早回退的 popstate 到达之前选择另一个会话，可能会回到列表一次；该窗口只有一个任务的长度。
