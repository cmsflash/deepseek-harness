# Agent Note: Browser local Session copy

Status: implemented

English | [中文](2026-11-07-browser-local-session-copy.zh.md)

## Problem

A Web thread existed only on the Host. Every reopen — a new tab, a reload — re-sent its opening window from the Host, so the first transcript row waited on the network, and reading a thread offline showed only what offline replay recorded. That recording was unusable: it stored decoded frames, so nothing in it could be checked against the [Session log chain](../../../../packages/session/session-persistence/README.md#the-session-log-chain), a busy thread rewrote its window every second, and a snapshot-shaped record replaced pages the reader had loaded. Releasing a Session disposed its window, so returning to a thread paid the full snapshot again, and nothing limited the event text one page's live Sessions held.

## Decision

The Host serves stored lines it can prove. The persistence chain exposes `storedLine(event)`: it re-encodes the event and returns the bytes only when their SHA-256 digest equals the chain's link at that seq, so nothing unproved is ever sent; a read-migrated log gets a chain over the exact header and event lines its successor publication will write ([chain definition](2026-11-03-resumable-session-follow.md)). The authenticated route `GET /api/session/lines` serves a range of stored lines, oldest first, as raw JSONL after one `SessionLinesHead` line; `have` checkpoints (up to 32 `seq:link` pairs the browser already holds) let the route continue from one past the highest matching one, locating where a diverged copy last agreed. `session/follow` gains `lines: true`: each record of a `resumed` opening and each live event frame becomes a line entry carrying the same link that record would carry decoded; snapshot openings stay decoded.

The browser keeps the copy. The `dsh-client-local-copy` client plugin runs one dedicated worker per tab from a Blob IIFE bundle, and IndexedDB database `dsh-local-copy` holds each thread as chunk records of up to 1 MiB of UTF-8 line bytes, one 32-byte link per line, written in single transactions that compare-and-swap the thread's stored head and head link, so two tabs cannot interleave chunks. One downloader per origin holds the Web Lock `dsh-local-copy/download`; it downloads one thread and one chunk at a time, sends its checkpoints, hashes every line from the stored previous link with `crypto.subtle`, waits after each chunk for at least `minPauseMs` or four times its own busy time, and starts at least three seconds after page start. A mismatch marks the thread `unverifiable` and requeues it for a repair that resumes from the highest matching checkpoint; a header rewrite replaces the copy from byte zero. Live and resumed line entries append to the copy under the same check, through the one byte comparison all link checks share: each line must hash from the stored head link and continue its seq.

Sessions open from the copy. `ClientSessions.registerHistorySource` installs it; the plugin registers synchronously and every source call awaits its IndexedDB probe, a failed probe answering as no copy, so a Session opening during an offline boot still asks the copy (one registration per page; ordinary Sessions only). A Session whose thread has a complete copy publishes its newest window from disk at once, marked `unconfirmed`, and opens `follow` with a resume point at the copy's head, so an unchanged thread transfers only the resumed opening's baselines. The first remote opening clears `unconfirmed`; a snapshot that replaces a locally opened window reports the divergence so the worker repairs the copy. Older pages, step expansions, and full-history interval reads consult the copy first and fall back to the Host for any read it does not cover.

Collapse runs in the browser for copy-backed windows. The paging, retention, digest, and turn-usage code moved to `history-shared` — inlined into the worker bundle, since a Blob worker cannot resolve workspace packages — so the worker builds the same pages the Host builds ([collapsed step digest paging](2026-09-01-collapsed-step-digest-paging.md)); retention and digests need only complete turns, so the worker computes them over the turns a page intersects and expands a withheld step from disk. Heavy parts shrink: streams read from the copy are cut to their first-token prefix, marked `stripped` until `requireFullHistory` re-reads the window's whole range at full detail, and `request/header` records carry a `headerKey`, so a Session keeps one header object per distinct content.

Released memory is bounded, not discarded. While a source is registered, the final release of an ordinary, opened Session disposes its scope and binding-owned UI state as any release does but keeps the Session object, with its window and follow, in a warm pool — after `warmFollowGraceMs` (default 30 s) its follow suspends — and a later `retain` binds a fresh scope to that Session, re-opening the follow from the newest held record through the journal's `adopt` ([Client Session references](2026-09-15-client-session-references.md) keeps ownership). One device-wide budget (`memoryBudgetBytes`, default 100 MiB desktop and 25 MiB phone) bounds the event text live Sessions hold; an idle pass evicts one Session's oldest page at a time, warm Sessions first and then by the page's last view, never a page a reported viewport intersects or follows, nor for `readerLoadGraceMs` (default 30 s) a page the reader's own older-history load added, and Chat's scroll reporting stamps viewport positions once a second. Pages under that protection, with every page between them and the viewport, may hold the total above the budget until their protection ends.

Device policy follows from the copy: desktop downloads every listed ordinary thread (`scope: 'all'`); a phone keeps only threads opened there under a 1 GiB disk budget, deletes the least recently opened copy first (never one opened in the last 10 minutes), and pauses while its page is hidden. Offline replay no longer records or replays `session/follow`: a held transcript comes from the local copy; while replaying, a follow offering a resume point stays open without items until the Host is back, and one without fails as a carrier failure. `ctx.remote.$offline` drives an "Offline" connection pill and a Chat notice; a copy that does not yet hold the whole log opens only while the Host is unreachable, its opening page marked `partial`, and the notice then adds that the saved copy is incomplete until a Host opening confirms the window (the Session snapshot's `incompleteCopy`). Reconnect costs fall on the control stream: each connection generation opens `session/control` once, sending `known` checkpoints of `asOfSeq` and chain link, and the baseline omits unchanged Sessions to `retained` ([Session observations](2026-08-25-session-observations-and-projection-owned-client-state.md) keeps the projection ownership).

## Alternatives considered

**OPFS.** One sync access handle per file serves a single reader, the `mode` option is missing on iOS, and private browsing fails; IndexedDB chunk records are readable from every tab of the origin and survive them.

**Per-line records.** Measured at about 7× the CPU of chunk records and 53–67 MB/s against 546 MB/s for 1 MiB chunks on desktop Chromium; a few thousand records per GiB keep cursor walks short.

**@noble/hashes.** `crypto.subtle` hashes at 441 MB/s in Chromium against 85–206 MB/s and needs no dependency; sequential awaits are fine.

**Hashing re-encoded events in the browser.** A decoded event re-encoded in the browser need not reproduce the stored bytes, and the browser cannot run the Node-based codecs; the Host keeps one definition by checking bytes it can prove.

**Compressing chunks.** Deflate-raw per chunk would shrink the copy but Chrome's new IndexedDB backend no longer compresses values itself; the copy is about the size of the event text, and compression stays a later phone option.

**Sending lines inside WebSocket frames.** JSON-escaping a line inside its frame adds about 10% and a slow reader blocks the socket's other streams; bulk lines travel over HTTP, compressed by the existing gzip middleware.

**Keeping headers on disk.** Chat's tool-change classification reads each header's full tool list, and the surface validator rejects an empty `header.tools`; sharing one in-memory object per distinct header keeps the default view working and saves most of the 0.53 GiB monthly header volume.

**A fixed count of warm threads.** The `warm-threads` branch kept the 8 most recently left Sessions with follows open; Zhuoran declined it on Nov 3, 2026 (79–120 ms switch-back, drawing dominates); the byte budget instead keeps unbounded warm Sessions, bounded by memory rather than count.

**A Host-wide event feed.** A separate feed of every live event to every page would move each thread's bytes several times over one connection; per-thread follows already carry the protocol and its gap checks.

## Consequences

A cold read of a historical log now pays one encode-and-hash pass to chain it (Node hashes at about 1.9 GB/s), and the Host re-encodes a stored line once per request. The copy is unencrypted in browser storage, as offline replay was; Safari's ITP deletes it after 7 days of Safari use without visiting the site, and a Home Screen web app keeps a separate, exempt copy. Subagent children are not copied, the Desktop app disables the plugin, and stored chunks stay uncompressed in this version. A complete copy rejoins the download queue when the session list reports a later prompt, a running-state change, or a projection watermark past its head that its last download was not made for, and fetches only the new lines; a closed thread is current after each prompt and turn end a page's list reports, while during a turn of a closed thread the copy keeps the turn's start. Deferred work: `workspace/follow` resume (87 KB per reconnect), conditional refetches of `session/list`, `settings/describe` and the other `connection/reset` listeners (about 69 KB, one revision each), digest-based request-header classification so headers can stay on disk, and Host unloading. Tests pin the chain against a `node:crypto` oracle, the worker's pages against the Host's functions, and an end-to-end reopen over the lines route.
