# Agent Note: 整轮用量随历史结束记录传输

Status: implemented

[English](2026-09-22-turn-usage-history-metadata.md) | 中文

## 问题

精确的轮次记账需要每次已启动的模型尝试，包括重试；浏览器的历史窗口却可能省略较早消息或折叠步骤的内部事件。从该窗口计算 token 和费用，会让已完成轮次的详情消失，即使持久日志包含完整记账。步骤 digest 描述过程数字，并非完整的尝试记账。

## 决定

Session Controller 在每条下发的 `turn/end` record 上附带 `turnUsage`，放在未修改的持久事件之外。Token-meter 拥有不依赖运行环境的记账折叠器。每个分页使用截至请求截止点的完整逻辑日志前缀，只为下发的结束记录输出汇总。因此，完整、折叠和精确区间读取无需获取隐藏详情也能保持一致。实时 follow 从 opening observation 初始化同一个累加器，此后每个已接受的持久事件恰好推进一次。

`null` 表示无法精确记账，包括生命周期证据不完整、用量缺失、总量冲突或不安全，以及费用总和不是有限数。缺少价格则贡献零并增加未计价计数。可选的缓存、推理和路由值保留各自的完整性规则。累加器只持有运行中的汇总、当前尝试和去重路由，不保留已完成尝试或事件正文。

Client journal 将此元数据保留在已接受的 entry 上。`ConversationMatch.record` 保留原始 entry，并满足 `record.event === event`，因此 target builder 可以通过已有的 append、prepend、替换和 location 重放路径读取权威元数据。轮次页脚消费结束记录中的结果，绝不改用部分原始事件的折叠结果。不引入额外的 Client 记账表或持久事件。

[折叠步骤分页决策](2026-09-01-collapsed-step-digest-paging.zh.md)继续拥有省略、覆盖范围和过程行数字。[费用显示决策](../feature/2026-09-11-billed-cost-display.zh.md)继续拥有显示范围、格式和未计价提示；本记录拥有不依赖已加载历史详情的记账交付方式。

## 考虑过的替代方案

**为显示用量而获取完整历史。** 否决，因为一个标量汇总不应抵消折叠历史节省的字节量和延迟加载详情的行为。

**累加现有步骤 digest 数字。** 否决，因为这些数字不包含重试尝试的记账以及价格和完整性信息，而且分页片段可能重复携带同一完整步骤的账目。

**发布包含所有轮次用量的整会话映射。** 否决，因为它会让每次 baseline 和更新随整个会话增长，而不取决于读者请求的历史。结束记录元数据的数量始终受下发记录约束。

**修改持久事件或重建轻量 Assistant 消息。** 否决，因为记账是读取模型，并非新的模型可见事实；缩短后的消息也会歪曲历史记录声称承载的精确事件。

## 影响

Session 日志格式与模型行为均不改变。同一元数据适用于普通地址和通过验证的 subagent 地址。历史替换随记录一起替换记账；分页与展开不会重新计算或重复累加已下发的总量。Host 分页读取仍扫描其日志前缀；本决策限制的是传输负载与实时保留的记账状态，而非冷读取工作量。

记账测试固定重试、可选字段完整性、零值与未计价金额以及溢出拒绝。Host 历史测试覆盖超过折叠分页预算的轮次、精确截止点、轮次中途开始的 follow 和不可用记账。Client 测试验证重放与替换时保留记录 identity 和权威 null。录制的浏览器检查确保 token 与美元药丸在折叠重载、展开和重新折叠后保持不变。
