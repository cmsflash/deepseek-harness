# Agent Note: Markdown 表格带上「复制为 markdown」控件

Status: implemented

[English](2026-08-24-markdown-table-copy-as-markdown.md) | 中文

## 问题

转录区里其他每一种区块表面都能复制——代码围栏经由 `CodeBlock` 的横幅按钮，文件改动经由 `DiffBlock`，命令输出经由 `TerminalBlock`，搜索结果经由 `SearchBlock`，整条消息经由 `MessageIconActions`——唯独渲染后的 markdown 表格不能。

表格恰恰是文本选择损失最大的区块。拖选渲染后的 `<table>` 得到的是单元格文本，列结构全部丢失：没有竖线，没有分隔行，没有对齐。最想把对比矩阵放进编辑器的读者，正是选择操作辜负的那位读者；而产出表格的模型早已写好了读者想要的那份 GFM。

## 决定

`renderTable` 改为通过新的 `TableBlock` 组件渲染，该组件带一个悬停显现的复制控件，控件把表格写回为 GFM。

### 这是真正的序列化，不是抓取 DOM

`tableToMarkdown`（`packages/client/ui-primitives/src/markdown/table-markdown.ts`）把解析出的 `Md.Table` 交给 `mdast-util-to-markdown`，并使用渲染器解析时所用的同一套 GFM 与 math 扩展。回读 DOM 就得从内联样式反推对齐、手工重新转义单元格文本；直接序列化渲染器已经持有的节点，则由语法自身的规则完成竖线、强调、链接、行内代码、删除线与行内 TeX 的转义。

该投影是规范化的而非逐字的：各列补齐到统一宽度，分隔行依 `node.align` 重建，因此排布参差的源码也复制为格式良好的 GFM。单元格中被转义的竖线保留为 `a \| b`，所以复制出的文本能重新解析回同样的单元格。

`mdast-util-to-markdown` 本就作为 `mdast-util-gfm` 的传递依赖存在于 lockfile 中；现在它成为 `ui-primitives` 的直接依赖，因为该包直接导入它。计入它的体积约为 9 KB（gzip），对照约 315 KB（gzip）的客户端基线。仅表格的扩展（`gfmTableToMarkdown`）单独不够——它在遇到 `delete` 与 math 节点时抛错，而渲染器的语法很容易把它们放进单元格。

无法序列化的单元格会撤下控件，而不是复制出被截断的表格。渲染器的节点联合是可合并扩展的，因此别处注册的语法可能把没有处理器覆盖的节点类型放进单元格。

### 流式期间撤下控件

流式表格的末行仍在生长，其投影会复制到解析了一半的末尾单元格。控件落在结算后的那一趟渲染上，围栏复制按钮与文件提及同样落在那里。

### 控件是滚动层的兄弟节点，宽表钩子随之迁移

`md-table-wide` 现在挂在新的 `.tableBlock` 包裹层而非 `.tableScroll` 上。`AssistantMarkdown` 用相对消息列测量的 margin 加宽该钩子，而这只有在消息列的块级子元素上才解析正确；把钩子留在如今已嵌套一层的滚动层上，会悄悄破坏突破布局。

按钮是滚动层的兄弟节点，理由与它不放在滚动层内相同：`.tableScroll` 横向滚动，内部的按钮会随读者滚动宽表而移出视野。作为定位区块的兄弟节点，它在任何滚动位移下都守住右上角——已针对真实的 312 px 溢出验证。

它覆盖在表头行的尾缘之上，而不预留空间，因为预留一行会把转录区里每张表格都下推一个控件高度。

### 可见性

悬停区块使其显现；`:focus-visible` 为键盘用户使其显现；`@media (hover: none)` 在没有悬停可用之处让它保持可见。复制完成的确认状态无论如何都保持可见，因此写入过程中滑开的指针——或由键盘发起的复制——仍能得到反馈。

填充色使用 `--dsw-alias-button-floating-*`，而非某个 `--dsw-alias-bg-*` 层级。这正是滚动条高度分级门禁所强制的实质差别：`MarkdownText.module.css` 内含滚动容器，因此该样式表里任何 surface token 都会带来重绑定滚动条的义务，而控件族的 token 正确地表明这是一个浮动控件，而非滚动条所依托的表面。

## 结果

- 覆盖含表格文档的八份 DOM 一致性 fixture 已重新录制。差异恰好是新增一层包裹、钩子迁移与该按钮；表格标记本身未动，流式 fixture 也正确地不含按钮。
- `markdown-wide-table.e2e.ts` 从区块读取突破相关事实，从滚动层读取残余滚动。其提交的几何 golden 未变，这正是填充/滚动/突破关系、前导 padding 对齐、键盘滚动与悬停滚动条行为在结构变更后依然成立的证据。
- 标签经由既有的 `codeLabels` 属性传入而非新开通道，因此表格控件与围栏控件在任一语言下都不会各自漂移。

## 曾考虑的替代方案

**切取原始 markdown 源码。**每个区块都带 `position` 偏移，因此表格源文本可零包体成本还原，并能复制出作者的原始排布。否决：结算渲染并未把源字符串向下传到 `renderTable`，而流式渲染器的冻结区块所带偏移是相对各自解析切片的。为省 9 KB 而把源字符串穿过两条路径，会让渲染器耦合上它本不需要的文本。

**由独立插件以 slot 贡献的方式注册该控件。**否决：`ui-primitives` 是静态的、不依赖 cordis 的包，没有 slot 依赖，且 markdown 渲染未暴露扩展点。为把它做成插件而新增扩展点，对一个刻意保持 cordis-free 的包而言是大得多的改动。
