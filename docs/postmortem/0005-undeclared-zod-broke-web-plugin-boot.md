# Post-mortem 0005: an undeclared `zod` broke the Web GUI at browser boot

English | [中文](0005-undeclared-zod-broke-web-plugin-boot.zh.md)

Status: resolved (fix on `wip/assistant-reply-read-aloud`)

## Executive summary

A new package exported a generated `./remote` artifact without declaring the `zod` that artifact imports. Every host-side check stayed green because pnpm's hoisted store answers `zod` at compile time, but the browser's frozen module table cannot, so the assembled GUI failed at boot. The fix declares the dependency and adds a manifest gate asserting that a `./remote` export implies every runtime dependency the generated artifact imports.

## Summary

Adding read-aloud introduced `@deepseek-ai/dsh-read-aloud`, whose `ReadAloudService` exposes one `@Remote('audio')` method. Typert therefore emitted `lib/typert.remote-client.js`, whose first line is `import { z } from 'zod'` — the request/result codecs are zod schemas. The package's `dependencies` listed only `@deepseek-ai/schemastery`.

`tsc`, `oxlint`, the 13,505-test unit suite, `test:gui`, `build`, and all 28 `doc-sync` gates passed. The failure appeared only when a browser loaded the assembled shell.

## Impact

The Web GUI could not boot while the branch was checked out. Recovery required reverting to `master` and rebuilding, which left four dangling symlinks under `$DSH_HOME/profiles/node_modules/@deepseek-ai/` that made `dsh --profile web --dump-config` exit 1 until they were removed. No data loss: sessions are durable, and the running server kept serving from already-loaded code until it was restarted.

## Root cause

The generated artifact is inlined into the browser bundle of whichever Client package imports it — here `@deepseek-ai/dsh-api-remotes`, through the new `import readAloudRemote from '@deepseek-ai/dsh-read-aloud/remote'`. The bundle-purity gate permits exactly that (`GENERATED_REMOTE` in `packages/client/tsdown.client.ts`: "wire contribution: inline is the point").

Inlining is mandatory rather than optional. `PLATFORM_MODULES` (`packages/client/web/src/platform.ts`) contains React, cordis, and three UI packages; `noExternal` in `clientConfig` states the rule directly — anything absent from the loader module table must inline, naming zod among the examples.

But a bundler can only inline what it can resolve, and pnpm's strict store symlinks declared dependencies alone. `packages/feedback/message-feedback/node_modules/zod` exists because that manifest declares zod; the read-aloud equivalent was never created. tsdown therefore left a bare `require("zod")` in the emitted factory, and at boot `makeRequire` (`packages/client/modules/src/client/system.ts`) walked seed → statics → cache → factories, found nothing, and threw. Its message already names the cause: "a build-time externals drift, or a forbidden cross-plugin value import".

## Why every host-side check passed

There is no `node_modules/zod` at the repository root, but there is `node_modules/.pnpm/node_modules/zod`. That hoisted path satisfies TypeScript and oxlint, so compile-time resolution succeeds for a package that never declared the dependency. Node running host code resolves it the same way. Only the browser, whose frozen module table is the sole resolver, distinguishes declared from merely reachable.

The scaffolding path made the omission easy. The manifest was generated by copying `message-feedback`'s field set, and `zod` was dropped on the reasoning that the new package used schemastery for its `Config` and nothing else — locally true, and wrong, because the dependency exists for the generated artifact rather than for anything in `src`.

## Fix

`packages/tts/read-aloud/package.json` declares `"zod": "^4.4.3"`, matching all five packages that already export `./remote`. Its knip entry ignores that dependency the way `cordis-host-runner` and `commands` do, because no file under `src` imports it.

`scripts/check-workspace-constraints.ts` gains `generatedRemoteDependencyErrors`, which asserts that a manifest with the canonical `./remote` export pair declares every member of `GENERATED_REMOTE_RUNTIME_DEPENDENCIES`. The check reuses the existing `hasTypertRemoteNavigation` predicate, and the list is a constant so a second generated import becomes a one-line change rather than a new rule. `scripts/workspace-constraints.spec.ts` proves the gate rejects a manifest missing the dependency, accepts one that declares it, ignores packages with no generated remote or a hand-written `./remote`, and holds for all six shipped remote packages.

The same investigation found a second omission of the same kind: `@deepseek-ai/dsh-client-read-aloud` was missing from the `paths` map in `tsconfig.base.json`, which `verify-cordis-config` reports because client package names prefix their group directory and cannot be matched by the generic wildcard.

## Lessons

**A generated artifact's imports are the owning package's dependencies.** Nothing under `src` needs to mention a module for the manifest to require it. Scaffolding a package by pruning a neighbour's manifest is exactly where this breaks, because the pruning decision is made by reading `src`.

**Compile-time resolution does not prove runtime resolution.** A hoisted store makes undeclared dependencies invisible to every static check. Only the frozen module table enforces the real rule, and it does so at browser boot — the last place the failure is cheap to find.

**A rule that only one artifact enforces needs a gate.** Five packages already followed this convention; nothing checked it. The convention was discoverable only by comparing manifests, which is how it was eventually diagnosed rather than prevented.
